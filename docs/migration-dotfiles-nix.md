- `configs/nvim/.config/nvim` — submodule, закреплённый на `ae8ee55`. В worktree он инициализирован, в исходной копии на момент проверки нет. Зафиксированный Nix flake input `6cc0d7d` происходит из того же репозитория и на 44 коммита новее. Решение о едином источнике не принято.
- На ПК `~/.config/nvim` — отдельная Git-копия на `6cc0d7d`, с незакоммиченным `lazy-lock.json`. Она не является Stow-ссылкой; перед передачей управления Home Manager необходимо отдельно разобрать локальные изменения. В NixOS к Neovim применяется Kotlin-патч, а Arch-установщик по умолчанию Neovim не устанавливает.
- В обеих изученных ревизиях Nix Home Manager подключён для `gklaptop` и ссылается на Herdr в `~/dotfiles/configs/herdr/.config/herdr`. Модуль Hyprland вызывает `~/dotfiles/bins/screen` и `~/dotfiles/bins/toggle_theme`. При изменении расположения нужно проверить эти зависимости и решить судьбу существующих ссылок.
- На `af5580e` Home Manager также управляет Neovim и Git-конфигурацией; остальные desktop-конфиги устанавливаются отдельно. Совместное использование Home Manager и Stow требует не допускать пересечения их целевых путей.
- `bins/toggle_theme` меняет ссылки тем внутри checkout для Hyprland, Foot и Quickshell. Неизменяемый Nix store нельзя использовать для этих изменяемых ресурсов без отдельного решения о хранении и применении состояния темы.
- В Nix есть SOPS-конфигурация и файлы секретов. Их содержимое в этот журнал не записывать; правила и способ переноса обсудить отдельно.

## Переход с gkdots на Home Manager

План для обсуждения, без удаления действующего установщика:

| Сейчас | Возможная замена |
| --- | --- |
| Локальный `gkdots/config.py` выбирает конфиги и бинарные ссылки | Общие модули Home Manager и выбор по хостам. Перед переносом разобрать фактический локальный `config.py`: он может отличаться от шаблона. |
| Stow устанавливает выбранные конфиги в домашний каталог | `xdg.configFile`, `home.file` или модули программ Home Manager. Для каждого пути проверить существующие файлы и ссылки Stow перед передачей владения. |
| Python связывает `bins/` и спрашивает перед заменой существующих файлов | `home.file` или `home.packages` с необходимыми зависимостями. Отдельно определить безопасное поведение при существующих файлах: оно не обязано совпадать с интерактивным установщиком. |
| Подготовка Alacritty и Foot генерирует отсутствующие файлы; Foot создаёт ссылку на тему | Разобрать в треде терминалов профили и изменяемые темы. Генерация сейчас не перезаписывает существующий результат; `toggle_theme` изменяет ссылки внутри checkout. |
| Не вызываемые по умолчанию функции устанавливают tmux и dwm | Не считать их активными; tmux отмечен как legacy, судьбу dwm обсудить отдельно. |

Порядок: в подготовленный standalone Home Manager для Arch постепенно переносить отдельные конфиги и скрипты, проверяя обе платформы и передачу файлов. Fish, Neovim, Foot и Quickshell уже разбираются отдельно. Только после переноса нужных функций и проверок решить судьбу `gkdots`. Установка Nix на Arch и отдельные цели Makefile `init`, `fonts`, `clean` требуют собственного решения; Home Manager не заменяет их автоматически.

## Открытые вопросы

- На ноутбуке до активации проверить `~/.config/hypr`, сохранить существующие файлы и ссылки, убедиться, что `~/dotfiles` содержит новый профиль, затем передать путь Home Manager и проверить сеанс Hyprland. До проверки существующую конфигурацию не заменять.
- Какие оставшиеся локальные изменения переносить, какими связанными группами и в каком порядке?
- Как учесть отставание исходного dotfiles от его локального `origin/master` и возможные будущие изменения исходного Nix после импорта обеих историй?
- Как поэтапно передавать файлы от существующего Stow к Home Manager без пересечения владельцев?
- Как организовать профили и генерацию Alacritty и Foot, submodule nvim, ссылки на `~/dotfiles` и обращение с секретами?
- Какие пакеты и настройки относятся к платформе, конкретной машине или общей пользовательской среде? Что устарело и может быть удалено после обсуждения?

Следующий небольшой шаг выбрать вместе с пользователем после просмотра одной из оставшихся групп локальных изменений.

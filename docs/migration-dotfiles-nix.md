## Рабочий эскиз, ещё не утверждён

- Разместить `flake.nix` и `flake.lock` в корне единого репозитория, а общие `configs/` и `bins/` хранить в одном экземпляре.
- Разделить Nix-код между `nix/hosts`, `nix/modules`, `nix/home`, `nix/packages` и `nix/overlays`, отдельно рассматривая настройки платформ и хостов.
- Существующие `gkdots` и Stow остаются доступными на время перехода Arch. Порядок передачи отдельных файлов Home Manager ещё не выбран.
- Назначать одного владельца каждому конкретному установленному файлу на конкретной машине, чтобы Stow и Home Manager не конфликтовали.
- Возможные примитивы: общие исходные файлы конфигураций и skills; выбор состава по хосту; установщики платформ, которые применяют этот выбор. Пакеты и системные настройки обсуждать отдельно от пользовательских конфигураций.
- Для Home Manager отдельно выбрать способ ссылок: в Nix store для воспроизводимого снимка или out-of-store для немедленного применения правок, как сейчас у Herdr. Пока выбор не сделан. При передаче файлов учитывать, что Stow может ссылаться на целые каталоги.
- Предложение использовать Nix store как основной вариант для Home Manager на NixOS не принято. Сначала следует учесть текущий подход Nix-репозитория и причины для возможного изменения.
- При утверждённом размещении потребуется согласовать относительные пути, два Makefile, правила SOPS и документацию.

Это ориентиры для обсуждения, а не команда создать дерево или перенести все файлы. Старая заметка [.tasks/20260330-192909/task.md](../.tasks/20260330-192909/task.md) предлагает отдельный Nix-репозиторий; её следует рассмотреть в свете текущей цели объединения, не удаляя автоматически.

При проверке удалённой ссылки 2026-11-04 GitHub `master` совпал с локальной ссылкой: `af5580e`. Какая ревизия фактически используется на ноутбуке, неизвестно. У проектов две отдельные Git-истории; обе нужно сохранить, способ объединения не выбран.

Herdr намеренно использует out-of-store ссылку на редактируемый checkout. Neovim подключён как закреплённый flake input с временным патчем; это отличается от submodule в dotfiles и требует отдельного решения.
- На Arch `make install` создаёт `gkdots/config.py` из `config.def.py`, если его нет, затем Python готовит и устанавливает выбранные конфиги через Stow. Она не является Stow-ссылкой; перед передачей управления Home Manager необходимо отдельно разобрать локальные изменения. В NixOS к Neovim применяется Kotlin-патч, а Arch-установщик по умолчанию Neovim не устанавливает.

## Переход с gkdots на Home Manager

План для обсуждения, без удаления действующего установщика:

| Сейчас | Возможная замена |
| --- | --- |
| Локальный `gkdots/config.py` выбирает конфиги и бинарные ссылки | Общие модули Home Manager и выбор по хостам. Перед переносом разобрать фактический локальный `config.py`: он может отличаться от шаблона. |
| Stow устанавливает выбранные конфиги в домашний каталог | `xdg.configFile`, `home.file` или модули программ Home Manager. Для каждого пути проверить существующие файлы и ссылки Stow перед передачей владения. |
| Python связывает `bins/` и спрашивает перед заменой существующих файлов | `home.file` или `home.packages` с необходимыми зависимостями. Отдельно определить безопасное поведение при существующих файлах: оно не обязано совпадать с интерактивным установщиком. |
| Подготовка Alacritty и Foot генерирует отсутствующие файлы; Foot создаёт ссылку на тему | Разобрать в треде терминалов профили и изменяемые темы. Генерация сейчас не перезаписывает существующий результат; `toggle_theme` изменяет ссылки внутри checkout. |
| Не вызываемые по умолчанию функции устанавливают tmux и dwm | Не считать их активными; tmux отмечен как legacy, судьбу dwm обсудить отдельно. |

Порядок: подготовить standalone Home Manager для Arch в текущем треде skills; затем по согласованию переносить отдельные конфиги и скрипты, проверяя обе платформы и передачу файлов. Fish, Neovim, Foot и Quickshell уже разбираются отдельно. Только после переноса нужных функций и проверок решить судьбу `gkdots`. Установка Nix на Arch и отдельные цели Makefile `init`, `fonts`, `clean` требуют собственного решения; Home Manager не заменяет их автоматически.
